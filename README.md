# 简历填写助手（resume-autofill-local）

一个需要手动授权和确认的 Chrome / Edge 简历填写扩展。个人资料保存在当前浏览器中，DeepSeek 负责匹配表单字段的含义，实际填写值由扩展从本机取出。可在每次确认时选择是否允许 AI 查看所选内容并辅助校对。

**使用流程：编辑资料 → 手动开启当前页检测 → 确认资料范围及添加选项 → 补足空条目并匹配 → 检查填写预览 → 确认写入 → 手动提交。**

不需要部署后端、安装 npm 依赖或上传 PDF。字段匹配需要联网调用用户自己的 DeepSeek API，并可能产生 API 费用。

## 功能

- 在独立设置页管理 16 类资料及技能、自我评价等综合信息；教育、工作、实习、项目和奖项分别保存。
- 支持预计毕业年月、学历与学位、专业大类、项目职责与成果，以及多条获奖内容。
- 按网页区块和条目编号匹配，拦截教育与工作混填、不同条目串位和开始 / 结束日期颠倒。
- 第一次确认后，可根据本次所选经历数量自动点击明确的“添加”按钮，补足空表单。
- 默认只发送字段描述和资料项名称；单独勾选 AI 辅助后，才发送所选资料值并复核预览与实际填写结果。
- 仅在用户手动开启后检测当前标签页，检测到简历表单时打开扩展确认窗口。
- 每次选择允许填写的资料；身份证号、详细地址、紧急联系人和薪资等敏感项默认不选。
- 展示字段与实际填写值的预览，经再次确认后才写入网页，默认跳过已有内容。
- 支持个人资料 JSON 导入与导出，不导入或导出 API 密钥。
- 支持常见原生表单及部分自定义下拉、日期组件，具体效果取决于目标网站。

字段设计参考了国内校招官网的公开页面、帮助文档和模板，见 [校招表单调研记录](docs/campus-form-research.md)。这不代表已在所有公司的登录后表单实测通过。

## 安装

支持 Chrome 120+，以及兼容相应扩展 API 的 Chromium 版 Edge。

1. 从 [GitHub 仓库](https://github.com/Alem42/resume-autofill-local) 选择 **Code → Download ZIP** 并解压，或使用 Git 下载：

   ```sh
   git clone https://github.com/Alem42/resume-autofill-local.git
   ```

2. Chrome 打开 `chrome://extensions/`；Edge 打开 `edge://extensions/`。
3. 开启“开发者模式”，点击“加载已解压的扩展程序”或“加载解压缩的扩展”。
4. 选择下载目录中**直接包含 `manifest.json` 的文件夹**，不要选择它的上级目录。
5. 点击浏览器工具栏中的扩展图标，打开“编辑个人信息与 API”。

日常使用无需 Node.js。只有运行源码测试时才需要安装 Node.js。

更新源码后，在扩展管理页点击“重新加载”，并刷新原来打开的招聘网页。重新加载扩展会清除默认的会话密钥，需要重新输入。卸载前请先导出需要保留的资料，浏览器会在卸载扩展时清除其本地存储。

从原项目更新时，格式有效的旧资料会迁移。旧 API Key、任意 Base URL 和待处理 PDF 结果会删除，不会把其他服务商的密钥自动用于 DeepSeek。迁移失败时设置页会提示，旧资料暂时保留。

## 首次配置

1. 在设置页填写个人资料。没有的信息可以留空，多条经历可用“上移 / 下移”调整顺序。
2. 填入自己的 DeepSeek API Key，选择模型。
3. 点击“保存个人信息与设置”，或点击“保存后测试连接”同时保存并验证接口。

接口固定为 `https://api.deepseek.com/chat/completions`，不能通过导入文件或网页消息修改。当前提供 `deepseek-flash` 和 `deepseek-v4-pro`，默认使用 Flash。API Key 由用户自行获取，详见 [DeepSeek 官方文档](https://api-docs.deepseek.com/)。

默认不勾选“在本机记住 API Key”，密钥仅保存在浏览器会话内。主动勾选后，密钥会持久保存到浏览器本地存储，扩展未额外加密。设置页不会回显已经保存的密钥，留空保存会继续使用现有密钥。

## 填写网页

1. 打开可信招聘网站的简历填写页面。
2. 先手动展开需要填写的区块。折叠、分页、弹窗中的内容需要先进入可见编辑状态。
3. 点击扩展图标，打开“本页手动检测”开关，只授权当前标签页主文档。
4. 检测到简历表单后，在扩展确认窗口核对完整网址，并选择本次允许填写的资料。
5. 核对“自动补足缺少的经历条目”（默认勾选）与“AI 辅助判断与校对”（默认不勾选）。点击“确认资料范围，准备表单并匹配”：可以创建空条目并调用 DeepSeek，此时尚未写入个人资料。
6. 检查填写预览，取消勾选不需要的字段。可在“调整对应资料”或“未匹配字段”中手动指定本次授权的资料；已识别的区块和条目不能跨类别调整。再次确认后才写入网页。
7. 回到网页逐项核对，手动保存或提交。

默认跳过已有值；要覆盖已有内容，必须主动勾选“允许覆盖已有内容”。AI 辅助开启时会校对对应字段的已有内容，发现疑点或无法判断的字段默认不选；校对请求失败时，全部预览项默认不选，需要人工检查并主动选择。填写结束后再展示实际结果的校对意见。校对只针对本次已建立对应关系的字段，不会上传整页或核实经历真伪，也不会自动生成修正值。

同类经历按设置页顺序，对应网页从上到下的条目；只选择其中部分经历时，所选条目会从网页第一条起连续对应。应先让设置页顺序与网站要求一致。合并的“实习 / 工作经历”区块依次使用本次选中的工作经历、实习经历；独立区块各自对应。

自动添加只补足缺额，已存在的条目也计入数量。必须有明确的经历区块及唯一、安全的添加入口；不明确、多个入口、点击后两秒内未发现新增结构或达到本次 40 次点击上限时，会停止并提示手动补足。不点击保存、上传、投递或提交按钮；网站的“添加”按钮仍可能触发其自身的网络请求。

取消或关闭确认窗口会停止检测、后续添加及尚未完成的 AI 请求。已添加的空条目和已经写入的值不会自动撤回。刷新、跳转或更换页面文档后，旧确认失效，需要重新开启检测。

## 个人资料存在哪里

资料存储属于**当前浏览器用户配置下的当前扩展**，不会写回项目源码，也不会因提交或推送 Git 仓库而上传。不同浏览器、用户配置或扩展 ID 的存储相互独立。本项目不使用 `chrome.storage.sync` 同步资料。

| 数据 | 存储位置 | 保留方式 |
| --- | --- | --- |
| 保存的个人资料 | `chrome.storage.local` 的 `profile` | 持久保存在本机，关闭或重启浏览器后仍保留 |
| 模型及是否记住密钥的设置 | `chrome.storage.local` 的 `settings` | 持久保存在本机 |
| 默认模式下的 API Key | `chrome.storage.session` 的 `secret` | 保存在内存，重启浏览器或禁用、重新加载、更新扩展后清除 |
| 勾选“在本机记住 API Key”后的密钥 | `chrome.storage.local` 的 `secret` | 持久保存在本机，未额外加密 |
| 当前检测、确认及预览 | `chrome.storage.session` 的 `flow_<标签页ID>` | 临时状态；预览包含本次匹配的资料值，开启 AI 后可能保存校对意见；实际网页读回值不保存到最终结果 |
| 手动导出的资料 | 用户下载的 `personal-profile.json` | 普通文件，由用户自行保管和删除 |

这些存储仅允许扩展自身的可信上下文访问，内容脚本不能直接读取。浏览器用户配置目录属于本机数据，其他能够访问该目录的软件或账户仍可能读取持久数据；它不是加密保险箱。

查看和清除资料：

- 日常查看或编辑：打开“编辑个人信息与 API”。
- 清除个人资料：点击“清空个人信息”，不会同时删除 API Key。
- 清除密钥：点击“移除已保存的密钥”，会清除本地及会话密钥。
- 查看实际存储：在扩展设置页打开开发者工具。Chrome 132+ 可在 **Application → Storage → Extension Storage** 查看 `local` 和 `session`。参见 [Chrome 扩展存储查看说明](https://developer.chrome.com/docs/devtools/storage/extensionstorage)。

浏览器管理持久存储的具体磁盘文件；项目目录中没有对应的个人资料配置文件。关于本地和会话存储的生命周期，参见 [Chrome Storage API 文档](https://developer.chrome.com/docs/extensions/reference/api/storage)。

## 哪些数据会发送出去

“本机资料”指个人资料值的保存、确认与填写由本机完成，字段匹配仍使用 DeepSeek 云 API。

- **默认发送给 DeepSeek：**网页字段的标签、占位符、`name`、组件类型、区块、条目编号、是否已有内容，以及本次允许填写的资料项名称和编号；不发送资料值或已有输入值。
- **仅主动开启本次 AI 辅助后额外发送：**匹配所需的已勾选资料值，以及已建立对应关系的网页字段的已有值、预览值和填写后实际读回值。复核包含已匹配但保留的已有内容；预览中取消勾选写入的字段也仍属于本次校对范围。
- **不发送：**未勾选的资料项、完整资料对象、网页 URL、网页全文、密码、验证码或文件内容。API Key 只作为固定 DeepSeek HTTPS 接口的认证信息。
- **确认写入后交给目标网页：**本次选择的实际填写值。网站及其脚本能够读取，部分网站会自动保存。

网页标签和占位符可能包含私人文字，因此字段描述本身也可能携带敏感信息。使用前应核对目标网站和填写预览。扩展不能保证招聘网站或 DeepSeek 的服务端行为。

## JSON 备份与恢复

设置页可导出或导入个人资料 JSON。导出的是当前表单中的内容；导入只替换设置页表单，检查并保存后才更新浏览器中的资料。

接受 16 个资料分类的键：`basic`、`education`、`work`、`internships`、`projects`、`awards`、`campus`、`research`、`publications`、`patents`、`languageCertificates`、`professionalCertificates`、`training`、`volunteer`、`portfolio`、`jobIntention`，以及 `languages`、`certificates`、`skills`、`selfEvaluation`、`interests`、`additionalInformation`。

[演示 JSON](examples/profile.example.json) 使用虚构资料，包含两段教育、三段项目和奖项，可用于了解格式或测试。请勿将演示资料提交给招聘网站。

未知字段、密钥、模型或 URL 配置及原型污染键会被拒绝。旧版包含 `llm` 的 JSON 需要先移除模型配置部分。导入文件最大 256 KB，每类经历最多 20 条，单个文本字段最多 20,000 字符；超出限制会报错，不会悄悄截断正文。

备份文件包含私人资料，请保存在项目目录之外。若在项目目录中暂存，`personal-profile*.json` 已在 `.gitignore` 中排除；忽略规则不能移除此前已提交的文件或清除历史记录。

## 限制与常见问题

- **没有检测到表单：**检测最长 60 秒。先展开填写区块，再重新开启“本页手动检测”。
- **经历字段不足：**第一次确认时允许自动补足；无法确定安全入口时，在网站上手动补足并重新检测。
- **部分字段没有填写：**可能已有内容、没有对应资料，或该组件暂不支持，请检查预览并手动补充。
- **区块未识别：**模型不会猜测未知区块中的重复经历；在预览中手动指定已授权资料，或手动填写。
- **顺序变了 / 输入框被替换：**失效字段会跳过，需要重新检测，不能沿用旧预览。
- **单选 / 复选、联动或特殊组件：**不操作 radio、checkbox、协议同意、附件上传；部分级联、自动补全、Shadow DOM 和自定义日期范围需要手动操作。学校自动补全可能要求点击标准校名，请核对实际显示与保存状态。
- **大型表单：**每次最多扫描 400 个字段，匹配 / 校对每批最多 60 个，可能产生多次 API 调用；每类最多 20 条经历。
- **iframe 内表单：**只支持主文档，不扫描或填写 iframe 内的表单。
- **受保护页面：**浏览器设置页、扩展商店等页面不允许注入脚本。
- **确认失效或接口超时：**确认有效期为 10 分钟，API 请求最长 25 秒，不会自动重试。
- **密钥需要重新输入：**默认会话保存模式下属于正常行为，也可以主动选择本机持久保存。

## 安全设计

- 无 PDF 导入、PDF.js、远程脚本或第三方运行时依赖。
- 无 `<all_urls>` 权限或常驻内容脚本，通过 `activeTab` 手动授权当前页面。
- 唯一持久网络访问权限为 `https://api.deepseek.com/*`。
- 本地及会话存储限制为 `TRUSTED_CONTEXTS`，网页不能通过消息读取资料或调用 API。
- 检测绑定标签页、文档 ID、完整 URL 和随机令牌，确认绑定扩展自己的确认窗口。
- 模型只能返回字段 ID 与资料项 ID；任意选择器、值、代码、重复映射或未授权编号均被拒绝。
- 本地验证已识别区块、条目序号和明确字段含义，跨教育 / 工作及起止日期映射会被拦截。未识别区块中的经历只允许用户手动指定授权资料。
- AI 校对只允许返回已授权字段的状态和理由，不能改写资料或执行操作；缺失或不可读取的结果标记为待人工判断。
- 填写使用扫描时保存的元素引用，并复核当前区块和条目位置。元素被替换、换位、隐藏、禁用或更改为密码框等情况会跳过。
- 自动添加在第一次确认后执行，限制按钮类型、区块、入口数量、新增结构及点击次数；个人资料写入仍需第二次确认。
- 排除密码、文件、隐藏、验证码、搜索及提交控件，默认不覆盖已有值。
- 不记录简历或密钥；API 不跟随重定向、不自动重试、不发送 cookies。

## 开发与测试

源码测试使用 Node.js，无需安装 npm 依赖。当前测试环境为 Node.js 24。

在仓库根目录，即包含 `package.json` 的目录运行：

```sh
node --test tests/*.test.js
```

也可以运行 `npm test`。Windows PowerShell 如果阻止 `npm.ps1`，可使用 `npm.cmd test` 或直接使用上述 `node` 命令。

测试使用虚构资料和模拟 API，不调用真实 DeepSeek，不产生 API 费用。真实接口需在设置页使用自己的密钥验证。

测试覆盖来源与令牌验证、取消与导航、跨区块 / 条目映射、缺额添加、保留已有内容、年月输入、分批匹配、AI 上传范围和前后校对。完整流程测试连接后台控制器与实际内容脚本，在模拟 DOM 中验证两段教育、三段项目的添加与填写。

手动测试可打开仓库中的 `test.html` 或 `test-add.html`。使用 `file://` 地址时，需要在扩展详情页启用“允许访问文件网址”。可先导入演示 JSON 并保存，在 `test-add.html` 使用自动补足选项；`?async` 测试延迟渲染，`?seed` 测试已有内容，参数可组合为 `?async&seed`。这些测试页面不连接招聘网站。浏览器实测与真实接口验证仍需自行进行。

- `options/`：个人资料和 API 设置页。
- `popup/`：当前页手动检测开关。
- `confirm/`：资料范围确认与填写预览。
- `background/background.js`：后台入口。
- `shared/controller.js`：存储、来源校验、授权流程和 API 调用。
- `shared/profile.js`：资料白名单、固定接口和模型结果验证。
- `shared/semantics-core.js`：共享的区块和字段含义规则。
- `content/sections.js`：区块 / 条目识别和受限的缺额添加。
- `content/content.js`：手动注入的检测与经确认的填写。
- `docs/campus-form-research.md`：官网调研依据与验证范围。
- `tests/`：源码安全与流程测试。
