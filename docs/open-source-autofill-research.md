# 简历自动填写开源实现调研与改造建议

调研日期：2026-10-20。对比基线：本项目 **2.7.0**，提交 `1f4969d`。

本轮按用户最新要求只交付调研。以下是源码审阅所得结论和后续建议，**不表示这些功能已经实现**。

## 1. 结论先行

建议保留当前的本机资料、手动启动、范围授权、填写预览、手动接管和不提交机制，将下一轮改造重点放在：

1. **为北森等组件家族建立适配层。** 企业名称或域名只是辅助线索，真正识别 Phoenix / Ant Design 等控件结构。
2. **把一次选择做完整。** 打开 → 等待／搜索 → 点选 → 检查待选状态 → 必要时点弹层“确定” → 读回已提交值 → 清理弹层。
3. **日期按当前视图逐级选择。** 读取目标精度，分别处理年份、月份、日期；已知必须逐级选择的控件优先走面板。
4. **将数据目录与页面操作分开。** 专业、学校、民族等目录解决“资料怎么录入、名称怎么对齐”；适配器解决“网站怎么真正接受选择”。
5. **补齐字段语义，再扩大匹配。** 自我评价别名、家庭成员、学位层次／门类、生源地和岗位调剂需要分别建模，不能靠提高模糊阈值混填。

没有找到一个可直接替换本项目、同时覆盖国内所有招聘系统和全部国内资料目录、又符合现有手动授权要求的现成实现。找到的项目各有可借鉴部分，也存在明显局限。

## 3. 同类项目具体怎么实现

### 3.1 S03-5/resume-autofill：组件、匹配、经历区块与记忆分层

它将选项评分与 DOM 点击分开：词表提供别名，匹配器处理否定、占位词和候选评分；组件层识别弹层，经历层补行并逐条填，记忆层保存用户指定的字段对应。值得借鉴的是结构划分和经用户确认的本机映射记忆。[匹配器](https://github.com/S03-5/resume-autofill/blob/45919a325be10f0960ea560fbdc28b7feef23d0d/content/matcher.js#L207)、[映射记忆](https://github.com/S03-5/resume-autofill/blob/45919a325be10f0960ea560fbdc28b7feef23d0d/content/memory.js#L253)。

其弹层逻辑比较点击前后出现的节点，并尝试 ARIA 关联；日期包含直接输入和逐级点选。需要注意：该快照的下拉验证允许根节点有非空文字即通过，不能证明组件确实接受了目标值。字段表也把生源地与籍贯等合并，不能照搬到国企表单。[控件实现](https://github.com/S03-5/resume-autofill/blob/45919a325be10f0960ea560fbdc28b7feef23d0d/content/widgets.js#L249)、[字段表](https://github.com/S03-5/resume-autofill/blob/45919a325be10f0960ea560fbdc28b7feef23d0d/content/sites.js#L20)。

### 3.2 qiuzhao-autofill：对这次“单选＋确定”最有参考价值

其内容脚本区分弹层归属、选项行和真实点击目标，支持包含 radio／checkbox 的候选。确认前检查选中状态或右侧已选区，再寻找归属弹层内的确认按钮，最后读回外框。日期路径也有关闭后复核和范围日期保留面板的处理。[候选与确认逻辑](https://github.com/Xplore-LAB/qiuzhao-autofill/blob/6c160b10c71f336dc20e736419aa54716ddb2e77/content/content.js#L707)、[日期与选择入口](https://github.com/Xplore-LAB/qiuzhao-autofill/blob/6c160b10c71f336dc20e736419aa54716ddb2e77/content/content.js#L1175)。

这是可借鉴的操作流程，不是已验证适配中国人保的证据。项目 README 自述北森仍有残留弹层与区块识别问题，独立的转转适配器也要求日期框可编辑。建议参考设计、自行实现；不直接复制许可未明确的源码。[已知限制](https://github.com/Xplore-LAB/qiuzhao-autofill/blob/6c160b10c71f336dc20e736419aa54716ddb2e77/README.md)、[独立适配器](https://github.com/Xplore-LAB/qiuzhao-autofill/blob/6c160b10c71f336dc20e736419aa54716ddb2e77/src/beisen-zhuanzhuan-adapter.cjs#L46)。

### 3.3 CampusApply-Agent：字段词表与 ATS 配置值得参考，执行验证不足

它先做规则匹配，再做关键词相似匹配，未解决部分交给 LLM；词表收录多种个人介绍／评价别名，资料记录有排序属性。这些有助于补齐我们的字段识别。[匹配引擎](https://github.com/hanjiayuan2025-coder/CampusApply-Agent/blob/6dee3305534b01722136108bc2a478103dd92368/extension/src/engine/matchingEngine.ts#L60)、[字段规则](https://github.com/hanjiayuan2025-coder/CampusApply-Agent/blob/6dee3305534b01722136108bc2a478103dd92368/extension/src/engine/fieldMappingRules.ts#L337)。

但其执行函数按标签类型调用填写函数，未抛异常就标成功，没有在该路径等待复杂自定义下拉提交。README 的多平台支持不能当作该弹层已适配的证据。[执行入口](https://github.com/hanjiayuan2025-coder/CampusApply-Agent/blob/6dee3305534b01722136108bc2a478103dd92368/extension/src/content/index.ts#L371)。

### 3.4 HelpResume：有 Phoenix 专用扫描，但存在提前报告成功

它识别 Phoenix 自定义选择器，使用原生 setter 和事件写入受控输入；选择列表依赖特定类名。问题在于部分填写函数安排定时回调后立即返回成功，不能据此统计候选是否找到、异步选择是否完成。可以参考扫描线索，不采用这种完成判定。[扫描器](https://github.com/funnyjacy/HelpResume/blob/caf6a78064cf5842249930bc2bd3448b429bb5cf/content/scanner.js#L93)、[填写器](https://github.com/funnyjacy/HelpResume/blob/caf6a78064cf5842249930bc2bd3448b429bb5cf/content/filler.js#L181)。

### 3.5 EasyApplyJobsBot：展示了平台专用自动化的另一条路线

它通过 Selenium 按 LinkedIn 已知按钮和流程推进，包含登录会话、步骤切换、简历选择及提交，部分分支提供 dry-run。这种流程对特定平台明确，但维护依赖该平台 DOM，不能直接解决国内 Phoenix 弹层。可参考步骤日志与限额控制；账号、Cookie 和自动提交路径不纳入本项目。[主流程](https://github.com/wodsuz/EasyApplyJobsBot/blob/70fe7484ebe78646fc8e2dd2612459f37eed7a9f/linkedin.py#L127)、[提交路径](https://github.com/wodsuz/EasyApplyJobsBot/blob/70fe7484ebe78646fc8e2dd2612459f37eed7a9f/linkedin.py#L465)。

公开 npm 中存在以下包，本次读取了 **3.3.55** 版本归档中的实现与 `package.json`，不是只看搜索摘要：

| 包 | 源码中能确认的能力 | 对我们的价值 |

中国人保的[公开表单入口](https://picc.zhiye.com/form?fromPage=editMyResume)可在未登录时读取 HTML 和加载器。本次下载的 `pcform-e1944db80b7bd4c43439.chunk.min.js` 与此前三一调研缓存逐字相同；其 Phoenix 分包中可观察到 `list-item-container`、`select-data-container`、`RadioChecked` 等左右选择器结构。这支持“按组件家族适配”的方向，**没有证明登录后的全部控件已运行验证**。[公开加载器](https://tcdn.bstatics.com/ux/ux-recruitment-portal-2022-form-pc/release/dist/pcform-e1944db80b7bd4c43439.chunk.min.js)。

据此建议采用三层证据：公开包测试 → 同版本公开分包结构核对 → 用户实际页面诊断／受控验收。三个层次分别记录，不能用前者替代后者。

## 5. 与我们的实现对比：已有能力和真正缺口

### 5.1 这次日志说明什么

用户最新匿名诊断中，扩展和内容脚本均为 2.7.0，识别 74 项、匹配 31 项，其中成功 23 项、未确认提交 8 项；AI 辅助和额外校对均关闭。

| 观察 | 可以确认的结论 | 还不能直接断定的部分 |
| --- | --- | --- |
| 民族失败时，弹层和选项计数均为 0 | 问题至少包含弹层发现／归属失败 | 不能只归因于“汉”和“汉族”近似度不够 |
| 某些学历、学位和学习形式能看到候选但未提交 | 候选存在与组件接受选择是两回事 | 还需区分候选含义不对、点击目标不对和缺少确认 |
| 43 个识别项未匹配，多项语义或区块未知 | 标签、区块和资料覆盖仍需改进 | 74 项可能含组件内部片段，不能直接当成 74 个真实业务字段 |
| 未开启 AI，仍发生这些失败 | 这次主要证据指向本机识别与交互 | 不能把失败归因于模型回答不佳 |

匿名日志不足以逐一还原字段文字，因此这里没有猜测未知字段对应哪些个人资料，也没有把用户学校、联系方式或经历写入报告。

对应实现：[资料模型](../shared/profile.js)、[字段语义](../shared/semantics-core.js)、[设置页排序](../options/options.js)、[内容脚本](../content/content.js)、[控件交互](../content/controls.js)。

两个具体缺口值得优先处理：

- `optionElements()` 当前排除包含 input 的候选节点，会漏掉一部分包着单选框的选项行；`choose()` 主要依赖点选后的显示变化，没有通用的“待选＋弹层确定”阶段。不能简单地放开所有页面 radio／checkbox，必须限制在归属弹层里。
- `fillCalendar()` 对格式明确的可编辑框优先尝试整串输入；对必须逐级点选的北森控件，应调整策略优先级。日期资料改成分开的选择器本身，不会自动修好网站交互。

还需把程序触发的原生选择事件与真实手动接管区分开。当前原生 radio 有同步保护；新增弹层点击路径也应纳入统一的程序操作标记。

## 6. 是否有现成的“学校、专业、语言、称谓、政治面貌全集控件”

本次未找到一套经过核验、可直接离线嵌入并覆盖上述全部内容的简历控件。更可行的是：**使用轻量选择控件，加载分领域、可追溯的数据目录。**

| 资料 | 找到的可靠来源或候选 | 适用范围与处理建议 |
| --- | --- | --- |
| 国内高校 | [教育部 2026 年全国高等学校名单](https://www.moe.gov.cn/jyb_xxgk/s5743/s5744/202606/t20260618_1441074.html) | 公开页面提供表格；开发期整理为离线 JSON，保留来源、版本、学校代码和名称 |
| 国际学校补充 | [Hipo/university-domains-list](https://github.com/Hipo/university-domains-list/tree/603e10f51b67c6553b9bca9aecc0db4c2417ed10) | [MIT](https://github.com/Hipo/university-domains-list/blob/603e10f51b67c6553b9bca9aecc0db4c2417ed10/LICENSE.txt)；名称和域名资料可补充国际院校，不等于全部学校的官方认证名录，中文别名仍需维护 |
| 本科专业类别 | [教育部 2026 年本科专业目录](https://www.moe.gov.cn/srcsite/A08/moe_1034/s3882/202604/t20260427_1434931.html) | 分学科门类、专业类、具体专业，不能把不同层级混成一个列表 |
| 研究生学科／专业 | [研究生教育学科专业目录（2022 年）](https://www.moe.gov.cn/srcsite/A22/moe_833/202209/t20220914_660828.html)及[调整对应表](https://www.moe.gov.cn/srcsite/A22/s7065/202506/t20250611_1193766.html) | 与本科目录分开保存；按用户学历与网页候选决定使用哪个体系 |
| 简历数据结构 | [JSON Resume schema](https://github.com/jsonresume/resume-schema/blob/b25e3f4bbafd349c2c5bbaa62602c03c228762db/schema.json) | 可参考经历数组、语言熟练度和不同精度日期；它不是招聘控件库，也不自带国内家庭／政治面貌目录 |
| 民族、政治面貌、家庭称谓、健康状况、语言 | 本机维护常用名称、别名与明确的自定义入口 | 无需依赖云端才能录入；网站可能使用不同选项体系，最终仍从网站真实候选中选择 |

JSON Resume 的旧仓库已归档，后续维护指向 [jsonresume.org 的 packages/schema](https://github.com/jsonresume/jsonresume.org/tree/master/packages/schema)，采用前应跟随现行入口。未明确许可的学校／专业整理仓库可以用来发现官方来源，不宜直接把整理成果整包复制进 MIT 项目。

资料页建议采用“搜索选择＋自定义输入”：本机目录给建议，学校不在列表或国外专业名称不同仍可保存。专业记录至少区分**学科门类、专业类、专业名称／代码**；学位记录区分**学士／硕士／博士等层次**与**工学／理学等门类**。不能把一个工学标签同时填进所有带“专业／学位”的框。

例如，同一段虚构教育经历可以同时有“学历：硕士研究生”“学位层次：硕士”“学位门类：工学”“专业类：计算机类”。它们不是四个近似说法，而是四种字段含义。网站若只写“学位”，应结合实际候选判断其要求层次还是门类，不能仅用标签猜测。

## 7. 推荐的技术改造方案

### 7.1 操作适配层，而不是公司 CSS 列表

建议拆为三层：

```text
资料层：原始值、标准名称、代码、别名、目录版本、用户排序
匹配层：网页字段 → 区块／条目 → 已授权资料 → 实际候选
操作层：通用控件 + Phoenix 选择／确认 + Phoenix 日期 + 其他组件适配
```

操作层统一提供打开、搜索、读候选、选择、确认、读回和关闭能力。域名、公开资源特征、ARIA、控件类名共同参与判断；不把检测到北森等同于允许无条件点所有按钮。

### 7.2 两阶段选项提交

对民族、专业类别等控件，建议流程为：

1. 保存原值与字段身份，打开并确定归属弹层。
2. 搜索后等待加载结束、候选稳定；必要时仅滚动该弹层的虚拟列表。
3. 按完全匹配、标准别名、唯一近似匹配的顺序选择；AI 仅协助判断已读取的候选编号。
4. 点击选项行内真正的选择目标，检查 pending 选中状态或右侧已选区。
5. 仅在当前归属弹层内寻找明确的确认按钮，并确认其可用；不触碰页面保存、投递、提交。
6. 弹层提交后读回外框目标值，再关闭残留弹层；超时或用户接管时停止本字段后续操作。

近似匹配不能跨越语义差异：群众与无党派人士、本人政治面貌与父母政治面貌、籍贯与生源地、学历与学位不是普通别名。

### 7.3 日期显式状态机

先确定网页精度和当前视图，再按“打开 → 年份 → 月份 → 日期（如需要）→ 确认 → 读回”推进。每次点击后重新获取当前面板，等待视图或选中状态变化，不能持有旧面板一直点击，也不能只按年月文字在全页找节点。

资料页可采用分开的年／月／日选择，但保存仍可兼容现有 ISO 字符串；只提供年月时不要伪造真实日期。范围日期作为一组操作，选完开始后可能仍需保持面板打开等待结束。继续沿用普通字段 5 秒、学校 10 秒的总预算，所有分支共用预算，不在超时后换策略继续写。

### 7.4 字段、分类与资料页

| 用户需求 | 建议模型与界面 | 关键验收点 |
| --- | --- | --- |
| 家庭情况 | `family[]`：姓名、称谓、电话、工作单位、政治面貌、职位、是否本公司员工；可排序 | 多成员不串条目，不拿本人手机号／政治面貌填父母 |
| 是否为本公司员工 | 对明确的本人／家属员工关系问题，提供“否”默认策略并展示在预览中 | 区分否定问法和“是否有亲属在本公司任职”等不同问题，不扩展到所有是／否题 |
| 民族、政治面貌、语言、称谓 | 常用本机选项、别名和自定义入口 | 父母独立保存；不根据本人身份或经历推断父母信息 |
| 生源地、健康状况 | 基本信息新增独立字段和常用选择 | 不把生源地等同户籍／籍贯，不凭空预设健康状况 |
| 是否同意岗位调剂 | 独立岗位调剂布尔项，与异地／城市调剂分开 | 从已保存意愿填写，不擅自替用户选择同意 |
| 学历／学位／专业类别 | 分层选择，目录保留版本与自定义名称 | 根据网页实际候选识别层级；旧自由文本保留，迁移有提示 |
| 自我评价 | 继续只保留一个资料项，增加个人评价、个人简介、自述等别名 | 描述栏不串到项目内容；重复网站栏位也能对应同一已授权资料 |
| 并列条目排序 | 保留现有上移／下移，增加禁用边界、可见序号和保存提示 | 新增、删除、重载与实际填写后顺序一致 |

### 7.5 AI 放在候选判断阶段，诊断记录操作阶段

当候选已正确取得，本机规则仍无法确定同义关系时，再请求 AI 选择候选编号；AI 不能修复根本没发现弹层的情况，也不应驱动任意 DOM 点击。

诊断建议增加控件家族、识别依据、当前阶段、候选数量、是否存在确认按钮、确认前后状态变化及超时阶段。默认仍不导出姓名、电话、证件号、经历内容或页面完整 HTML；需要重建问题时优先制作脱敏结构夹具。

## 8. 实施优先级与验收计划

| 优先级 | 工作 | 验收标准 |
| --- | --- | --- |
| P0 | 北森左右选择器：发现、搜索、行内选择、确定、读回 | 民族和专业类别的回调接受目标值；不以输入词或待选区内容提前算成功 |
| P0 | 北森分步日期与范围日期 | 年、年月、年月日均按控件精度提交；从当前年份跨年选择正确；不能提交则在总预算内跳过 |
| P0 | 自我评价别名与学位含义拆分 | 评价稳定对应同一资料；学历、学位层次、门类互不串填 |
| P1 | 家庭情况、生源地、健康和岗位调剂 | 保存、导入导出、预览、匹配、填写和取消全链路通过 |
| P1 | 离线目录和资料页选择 | 目录无网络也能检索；保留自定义值；旧资料可迁移；不能自动把国外专业硬改为国内代码 |
| P1 | 排序体验与多条经历添加 | 所有数组分类顺序持久化；按缺额添加；“是否有经历”前置门槛明确时单独适配 |
| P2 | 用户确认后的本机映射记忆 | 只记字段对应与结构特征，站点改版后可失效；用户可查看、删除 |

回归样式必须包括：普通下拉、异步学校搜索、包含 radio 的选项行、左右待选确认、层级／虚拟列表、逐级年月日、范围日期、动态添加记录与编辑中节点替换。

每个夹具分别核对匹配覆盖、真实组件接受值、跳过原因、超时后的迟到操作和手动接管。现有 7 组组件与完整表单回归继续保留，但要补上此前未覆盖的左右选择器和实际 Phoenix 包测试，不能再把通用组件通过率当作官网覆盖率。[现有测试范围](component-compatibility.md)。
