## 对实现的影响

1. **同名字段依赖区块和条目。** “开始时间”“结束时间”“描述”等不能仅凭字段名映射。扫描先识别教育、工作、实习、项目等上下文，再确定从上到下的条目编号；后台进一步验证，模型跨区块或串条目时拒绝写入。
2. **资料结构覆盖不同用途。** 教育中区分学历、学位、专业大类；项目区分概述、职责和成果；奖项区分国家 / 省级等“级别”与一等奖等“等级”。增加校园、科研、论文、专利、语言考试、资格证书、培训、志愿、作品集。部分分类属于基于常见求职用途的扩展设计，并非宣称每家公司都有这些字段。
3. **毕业信息精确到月。** 基本信息新增 `expectedGraduationDate`，格式 `YYYY-MM`。各教育记录仍各自保留起止时间；不能把本科结束日期拿来填写预计研究生毕业日期。模型与本地规则共同区分含义。
4. **多条记录按缺额补足。** 第一次确认后，根据所选资料条数减去网页已有条数，点击明确的“添加教育经历 / 添加项目经验”等入口；每次等待新增结构，最多 40 次。不支持的入口提示手动补足，第二次确认前不写资料。
5. **不硬编码公司专用 CSS。** 官网会改版，公开页通常无法展示全部编辑状态，因此使用标题、ARIA、通用记录容器及字段锚点。多个添加入口、隐藏区块、不可辨别的记录边界优先停止或交给用户处理，不宣称通用规则能识别所有页面。
6. **AI 只辅助，不代替确认。** 默认只上传字段描述和资料名称。用户单独允许后，上传已勾选资料值及对应字段的已有值 / 读回值，检查语义和条目是否一致。模型只能返回状态及理由，不能直接修改、编造经历，也不能证明经历真实。
7. **学校及特殊控件保留人工核对。** 学校自动补全、级联地区、单选 / 复选、日期范围或协议可能有独立交互。当前不操作 radio、checkbox、上传和提交；通用输入成功不代表网站已保存，需核对标准选项和实际结果。

## 验证范围

自动化测试使用虚构资料、模拟 API 和 DOM，执行真实后台控制器及内容脚本。验证包括两段教育、三段项目的补足与填写，区块 / 条目约束，已有值保留，预览后条目换位，年月输入，取消 / 导航，危险按钮拒绝，分批匹配，以及 AI 内容上传范围和前后校对。

`test-add.html` 提供空区块、合并实习 / 工作、奖项以及延迟添加、已有内容的手动测试场景；`examples/profile.example.json` 提供虚构资料。尚未登录上述公司的招聘账户逐个实测，真实控件兼容性与 DeepSeek 回答质量需要在实际页面继续验证。
