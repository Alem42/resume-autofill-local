## 测试方式与边界

该 agent 环境没有 CUA 浏览器工具，因此使用项目 `tests/browser/chromium.mjs` 启动隔离 Edge，通过真实浏览器鼠标、键盘事件逐步操作，读取组件接收值并人工检查截图；未使用仅修改 DOM 值的方式代替选择，也未把既有自动断言的输出当作本次手动验收。

测试地址为 `test-beisen.html` 和真实的 `options/options.html`（仅替换扩展消息接口为本机虚构资料 mock）。Select、SelectList、DatePicker、MonthPicker 来自实际 Phoenix 3.3.55 包；民族、专业类别的左右待选与确定弹层属于公开结构的测试夹具，不能视为已经登录中国人民保险完成实站测试。

截图留在忽略目录 `.preview/beisen-manual-qa/`，不包含真实个人资料。

## 操作中发现并交回修复的问题

1. **中止显示异常**：运行中点击中止，高亮已清除且后续写入停止，但测试工具把停止结果当正常完成，显示“填写 undefined、跳过 undefined”并把未执行内容算验收差异。已交主 agent 修复测试工具的中止分支。
2. **仅年份的日期字段误走普通下拉**：最新夹具教育第 2 条开始时间为 `data-format=YYYY`。完整运行匹配 62/62、填写 61、跳过 1；唯一未填写为该字段，扫描类型 `custom-dropdown`，执行阶段为 `choice`，未切换到日历年份选择。已交主 agent 修复与复测。
3. **并发操作提示**：用户重新编辑已完成的学校时，程序可能已经打开下一学校的 portal。此时按页面第一个候选点击会产生歧义。该次没有作为“当前高亮字段接管”成功证据；需要按所属弹层识别，并在继续打开其他菜单前尊重用户正在操作的菜单。

上面的历史记录保留了发现过程；最终修复结果应结合主 agent 的回归记录核对。

## 第一轮修复后的独立复测

- 刷新主 agent 重新构建的页面，点击民族的 `RadioUnchecked` SVG，右栏出现汉族，外部尚未提交；点击确定后才接收汉族。没有借用普通 input 模拟这个 SVG 目标。
- 仅年份 DatePicker 手动点击 2020，组件接收 `2020`，外框显示 `2020`，弹层关闭。年字段误分类问题另由主 agent 完整执行回归核对。
- 开始后中止，进度现在显示“已中止填写，已填内容保留。”，高亮数为 0，协议和投递计数均为 0，原来的 undefined 汇总已消失。
- 旧学校重开冲突复核：首所学校已接收后重新打开并搜索另一虚构学校，候选真实存在，但程序继续向后滚动，测试夹具的该 popup 一度位于视口上方（top=-1005px）。已给主 agent 发送截图和复现步骤，需同时调整夹具视口定位及自动填写期间对用户活动的尊重。

## 手动接管修复后的独立复测

1. 第一所学校由程序接收后，立即重新打开该学校，输入另一虚构学校的部分名称；等待约 2.1 秒。
2. 程序停在 8/62，候选位于视口内（top=468.875px），出现棕色“等待你完成手动选择……”提示，没有继续抢滚动。保留约十余秒也没有把人工等待算成自动填写超时。
3. 真正点击属于该弹层的准确学校候选，组件接收另一学校；弹层关闭，等待提示消失，程序继续专业类别等后续字段，没有一直等待。
4. 后续处理到 41/62、41 填写、0 跳过时，手选学校仍被保留。再次打开旧学校后点击中止，等待提示和当前高亮均清除，页面显示已中止，手选值不变，协议和投递计数仍为 0。
